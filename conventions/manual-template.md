# 標準マニュアルテンプレート

すべてのマニュアルページはこのテンプレートに従う。
人が手書きするときも、登録 Bot（LLM-1）が整形するときも、同じ型を使う。

理由:
- 人が見ても構造が揃う（一元化環境として機能）
- チャンク化したとき見出し単位で意味のある分割になる
- メタデータが機械的に拾える
- 検索精度が安定する

---

## テンプレート本体

```markdown
---
title: {動詞 + 目的語。例「国内出張の経費を精算する」}
type: howto            # tutorial | howto | reference | explanation
audience: 全社          # 全社 | 経理部 | マネージャー 等
owner: {責任者のメール}   # 例 tamura@example.com
review_due: {YYYY-MM-DD} # 見直し期限
status: draft           # draft | published | deprecated
canonical: false        # この事実の正典なら true
related:                # 関連ページの論理パス
  - /manuals/...
source_files:           # 元になったファイル名（任意）
  - keihi_v1.2.xlsx
---

# {タイトルと同じ}

## 概要
（1〜3文。このマニュアルが何のためのものか。検索ヒット率を上げる要約）

## 対象者
（誰向けか。前提知識）

## 前提条件
（事前に必要なもの・状態。アカウント、権限、ツール等）

## 手順
（番号付き。連番厳守。各ステップは動詞で始める）

1. {最初の操作}。
2. {次の操作}。…の後に行う。
3. …

## トラブルシューティング
（よくある失敗と対処。「症状 → 原因 → 対処」）

## よくある質問
（Q&A 形式）

## 関連ページ
- [[/manuals/...]]（リンクで参照。内容を重複させない）

## 改訂履歴
| 日付 | 変更者 | 内容 |
|------|--------|------|
| {YYYY-MM-DD} | {名前} | {変更内容} |
```

---

## type 別の使い分け（Diátaxis）

| type | 目的 | 含めるべき節 | 例 |
|------|------|-------------|----|
| `tutorial` | 学習（初めての人を導く） | 概要・前提・手順（丁寧に）・次のステップ | 経費精算をはじめて使う |
| `howto` | 作業遂行（特定タスク） | 概要・前提・手順・トラブル | 海外出張の経費を精算する |
| `reference` | 仕様確認（早見表） | 概要・一覧表/定義（手順は持たない） | 経費科目一覧・上限額一覧 |
| `explanation` | 理解（なぜ） | 概要・背景・考え方（手順は持たない） | 経費ポリシーの考え方 |

**1 ページ 1 type**。混在させない（howto と reference を 1 ページにしない）。

---

## 必須ルール

1. **タイトルは「動詞 + 目的語」**。"経費精算" ではなく "経費を精算する"。
   ただし reference/explanation は名詞でよい（"経費科目一覧"）。
2. **1 ページ 1 タスク完結**。スクロール 3〜10 画面が目安。
   大きすぎたら分割、小さすぎたら統合。
3. **1 事実 1 ページ（DRY）**。同じ事実を複数ページに書かない。
   他ページからはリンク参照する。
4. **バージョン・日付はタイトルに入れない**。メタデータ（frontmatter）に持つ。
5. **owner と review_due は必須**。責任者不明・更新時期不明を作らない。
6. ライティングの細則は [writing-style.md](writing-style.md) に従う。

---

## パス命名規則

```
/manuals/<部署>/<業務カテゴリ>/_<type>/<タスク名>
```

例:
```
/manuals/経理/経費精算/_howto/国内出張の経費を精算する
/manuals/経理/経費精算/_reference/経費科目一覧
/manuals/人事/勤怠/_howto/勤怠を修正する
```

- 階層は **3 階層まで**（部署 / カテゴリ / タスク）。深くしすぎない。
- ドラフトは `status: draft` で区別する（パスは本番位置でよい）。
